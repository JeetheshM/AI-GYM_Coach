1. THE 30-SECOND ELEVATOR PITCH
--------------------------------------------------------------------------------
"I built a real-time, privacy-focused AI Gym Trainer using Streamlit, MediaPipe,
OpenCV, Groq LLM, and Google Text-to-Speech (gTTS). 
The app captures webcam video via WebRTC, runs 30+ FPS pose estimation locally 
to track 33 body joints, evaluates form using vector geometry, and uses a hybrid 
AI system (Rule Engine + Groq Llama 3.3 LLM) to deliver proactive real-time 
voice coaching whenever bad form is detected."


2. MODULE-BY-MODULE RESPONSIBILITY BREAKDOWN
--------------------------------------------------------------------------------
📁 main.py
   └── The UI entry point. Initializes Streamlit configuration, loads CSS styles,
       manages user authentication, renders the WebRTC streamer, sets up session
       state defaults, and handles automatic audio playback.

📁 services/vision/exercise_video_processor.py
   └── Contains VideoProcessorClass (inherits from VideoProcessorBase).
       Processes every WebRTC video frame, runs MediaPipe Pose Landmarker,
       calls specific exercise detectors, draws skeleton overlays using OpenCV,
       and manages thread safety using a Python threading.Lock().

📁 detectors/ (squat.py, pushup.py, biceps_curl.py, etc.)
   └── Mathematical rule engines for each exercise. Converts raw 3D pose landmarks
       into biomechanical angles (e.g., knee angle, back angle), counts repetitions,
       and flags form errors (e.g., "TOO HIGH", "SAGGING", "SWINGING").

📁 services/tracking/metrics.py
   └── Bridge between the background WebRTC thread and Streamlit's UI thread.
       Runs sync_metrics_update() to poll metrics from the VideoProcessor,
       updates st.session_state, saves completed set history to SQLite, and
       triggers voice feedback events.

📁 services/coaching/voice_pipeline.py
   └── Orchestrates the coaching triggers. Translates raw metrics into technical 
       issues (_find_form_issue), applies a 5-second cooldown throttle to prevent
       API spam, and coordinates calls between LLM Coach and Text-To-Speech.

📁 services/coaching/llm.py
   └── Wraps the Groq API client running Llama 3.3 70B. Takes the technical issue,
       combines it with a system prompt, and generates motivational, natural 
       coaching responses.

📁 services/coaching/tts.py
   └── Text-To-Speech service using gTTS (Google TTS). Converts the LLM's string
       into MP3 audio bytes using an in-memory BytesIO buffer.

📁 services/persistence/exercise_repository.py
   └── SQLite database layer storing user login credentials and workout history 
       (reps, sets, total active duration, date).


3. END-TO-END SYSTEM ARCHITECTURE & DATA FLOW
--------------------------------------------------------------------------------
[ Browser / Webcam ]
         │
    (WebRTC Stream)
         ▼
[ VideoProcessorClass.recv() ]
   ├── 1. Convert WebRTC frame (NDArray) -> BGR format
   ├── 2. Flip image horizontally (cv2.flip) for mirror view
   ├── 3. Convert BGR -> RGB & pass to MediaPipe Pose Landmarker (Runs offline)
   ├── 4. Extract 33 Pose Landmarks (x, y, z, visibility)
   ├── 5. Pass landmarks to active Detector (e.g. SquatDetector)
   │        └── Calculate joint angles & Rep counts using vector geometry
   ├── 6. Draw Skeleton (cv2.line) & Status Overlay (cv2.putText)
   └── 7. Return modified BGR frame to WebRTC browser video player
         │
  (latest_metrics)
         ▼
[ sync_metrics_update() in main UI loop ]
   ├── 1. Safely pull metrics using thread lock
   ├── 2. Update Streamlit session state (rep counts, angles, progress bars)
   ├── 3. Check for form issues or set completion events
   └── 4. Pass event to VoicePipeline
         │
         ▼
[ VoicePipeline & AI Generation ]
   ├── 1. _find_form_issue() maps raw metrics to technical issue string
   ├── 2. Check 5-second cooldown throttle (now - last_spoken_at >= 5)
   ├── 3. Call Groq Cloud API (Llama 3.3 70B) -> Generates Coach Persona response
   ├── 4. Pass response text to gTTS -> Fetch MP3 audio bytes
   └── 5. Set st.session_state.audio_to_play & trigger st.rerun()
         │
         ▼
[ Audio Autoplay ]
   └── Hidden HTML audio player (<style> display:none </style>) autoplays MP3.


4. DETAILED TECHNICAL "HOW & WHY"
--------------------------------------------------------------------------------
A. Frame Format Conversion (Why BGR -> RGB?)
   • OpenCV natively reads image matrices in BGR (Blue-Green-Red).
   • MediaPipe models are trained on standard RGB (Red-Green-Blue).
   • Therefore: WebRTC (BGR) -> Flip -> RGB -> MediaPipe -> Overlay on BGR -> WebRTC.

B. Biomechanical Math (How joint angles are calculated)
   • For any joint (e.g., Knee), we select 3 landmark points: 
     A = Hip, B = Knee (vertex), C = Ankle.
   • We calculate vectors BA = A - B and BC = C - B.
   • Angle θ is calculated using the arctangent function (atan2):
     θ = |atan2(Cy - By, Cx - Bx) - atan2(Ay - By, Ax - Bx)|
   • Converted to degrees: angle = θ * (180 / π). If angle > 180, angle = 360 - angle.

C. Hybrid AI Approach (Rule Engine + LLM)
   • Why not pass raw landmarks directly to LLM?
     1. LLMs cannot process 30 FPS 3D spatial numbers accurately.
     2. High latency (~1s) and astronomical API costs ($$$).
   • Solution: 
     1. Python Rule Engine does deterministic math (0ms, 100% accurate).
     2. Groq LLM acts as the creative speaker to convert math outputs into 
        human-like, encouraging spoken advice.

D. Thread Safety & Synchronization
   • WebRTC runs frame processing asynchronously in a background thread.
   • Streamlit runs UI rendering in the main thread.
   • To prevent race conditions or crashes when reading/writing metrics simultaneously,
     VideoProcessorClass uses `threading.Lock()` during get_latest_metrics() 
     and set_latest_metrics().

E. Rate Limiting & Throttling
   • Problem: Calling Groq LLM and Google TTS on every frame (30 times/sec) would 
     crash the app and get the IP banned (Error 429: Too Many Requests).
   • Solution: `VoicePipeline` enforces a 5-second cooldown timestamp check:
     `if now - self.last_spoken_at < 5: return None`


5. INTERVIEW QUESTIONS & MODEL ANSWERS
--------------------------------------------------------------------------------
Q1: Why did you use streamlit-webrtc instead of OpenCV's cv2.VideoCapture(0)?
A:  "cv2.VideoCapture(0) attempts to access a webcam attached directly to the 
    host machine running Python. In a web-deployed application (like Streamlit 
    Cloud or AWS), Python runs on a server in the cloud where no physical camera 
    exists. streamlit-webrtc streams video frames directly from the user's web 
    browser over WebSockets/ICE network protocols to the server for processing."

Q2: Why use Groq API instead of OpenAI GPT-4?
A:  "Real-time voice feedback requires minimal latency. Groq's LPU (Language 
    Processing Unit) infrastructure yields speeds of ~500 tokens/second for Llama 
    3.3 70B, bringing response latency down to ~150-200ms. This ensures audio 
    coaching reaches the user while they are still in the middle of their exercise set."

Q3: How do you handle poor lighting or obscured body parts?
A:  "MediaPipe assigns a visibility score (0.0 to 1.0) to each landmark. My code 
    filters out landmarks with visibility < 0.7. If key joint visibility drops below 
    this threshold, the system displays a visual warning ('NO POSE DETECTED') and 
    suppresses metric updates to avoid false rep counts."

Q4: Is user video privacy maintained in your app?
A:  "Yes, 100%. Video frames are processed in-memory in real-time. No video 
    recordings or images are ever saved to disk or transmitted to cloud servers. 
    Only anonymized numerical metric summaries (e.g. rep counts, set duration) are 
    saved to the local SQLite database."

Q5: How does the audio autoplay work without user interaction?
A:  "Modern web browsers block unprompted audio autoplay. To bypass this seamlessly 
    within Streamlit, I injected custom CSS to hide Streamlit's native audio widget 
    (`data-testid='stAudio' {display: none;}`) and set `autoplay=True` on `st.audio()`. 
    Because the user initiates the camera session by clicking 'Start Workout', browser 
    autoplay restrictions are satisfied."
